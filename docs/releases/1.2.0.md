# PP-DocLayoutV3 SDK 1.2.0 发布说明

本版为兼容的功能更新，npm 包为 `web-sdk-pp-doclayoutv3@1.2.0`。模型元数据版本继续为 `1.0.2`，未重新转换模型，也未改变输入、输出、标签和后处理契约。

## 新增能力与迁移

- 新增顶层 `clearCurrentModelCache({ modelId, version })`，清理指定模型及版本的全部精度；检测器实例的同名方法根据实际加载模型确定身份。
- 新增 `clearAllModelCache()`，只清理本 SDK 命名空间。旧 `clearModelCache()` 保持 SDK 全清语义，其他 SDK 和其他源站存储不受影响。
- 新增 `estimateModelCache(identity?)`，分别报告内存字节、持久缓存字节和条目；可选的 `originUsageBytes`、`originQuotaBytes` 表示整个源站，不能当作本 SDK 的模型大小。
- 新增标准加载耗时 `modelCacheReadMs`，旧 `modelCacheMs` 保留且同值。无需修改已有调用；新集成优先读取标准字段。
- 缓存清理与写入串行，清理使此前下载的待写入缓存失效；旧损坏校验不能删除清理后写入的新缓存。普通历史缓存键继续兼容；包含分隔字符的模型身份使用独立编码键，避免误删其他模型。
- Demo 展示当前模型容量、当前模型清理与 SDK 全清入口；清理会取消并等待当前任务，释放 Worker 会话，显示忙碌和失败状态。加载、推理或切换来源期间暂停应用自定义清单，同时取消迟到的初始化清单请求，防止缓存身份被旧会话覆盖。

安装：`pnpm add web-sdk-pp-doclayoutv3@1.2.0`。双语 [API 文档](../zh-CN/api.md) 和 [English API](../en/api.md) 提供完整缓存语义。Vanilla Vite、React、Vue、微信 H5/WebView 示例使用当前本地 SDK，CDN 示例固定到 1.2.0。

## 模型来源、许可证与资源

上游为 [PaddlePaddle/PP-DocLayoutV3_safetensors](https://huggingface.co/PaddlePaddle/PP-DocLayoutV3_safetensors)，模型、SDK 与 ONNX 衍生产物使用 Apache-2.0。归属与使用说明见 [第三方声明](../../THIRD_PARTY_NOTICES.md)。模型有 33,175,165 个参数，输入为 `[1, 3, 800, 800]`。

当前清单为 `models/pp-doclayoutv3/manifest.json`；资产由 Git LFS 保存，并通过 [Pages 模型清单](https://chenmohan123.github.io/web-sdk-PP-DocLayoutV3/models/manifest.json) 分发。npm tarball 不包含 ONNX 大文件。

## 后端与已知限制

运行时为 ONNX Runtime Web 1.27.0，提供 WASM/CPU 和 WebGPU、主线程和 Worker 两种执行方式。当前模型的 FP16、FP32 均已有 WASM 和物理 WebGPU 验证证据；全自动模式优先选择 WebGPU FP16，按清单与能力尝试其他组合。显式指定后端或精度时默认不允许回退。

- 本次缓存和打包验证使用极小模型，不扩展真实 PP-DocLayoutV3 的性能或跨设备兼容性承诺。历史模型证据仍保留在 `tools/model-pipeline/reports/1.0.2/`、`benchmarks/1.0.1/`；环境限制见 [兼容性文档](../zh-CN/compatibility.md)。
- 不支持 FP64，也不提供 WebNN/NPU 或微信小程序原生推理；微信接入通过 H5/WebView 承载。
- 首次下载约 71 MiB 或 136 MiB；HTTPS、CORS、内存和浏览器存储配额仍是部署约束。持久缓存使用 Cache Storage，失败时可回退到当前 JavaScript 环境的内存。
- 顶层缓存 API 不会自动释放调用方持有的其他检测器，也不能中止其他标签页或独立 JavaScript 环境的任务。`cache: false` 的独立管理器通过检测器实例清理。使用方仍需协调任务并调用 `dispose()`。
- 缓存容量不包含 ONNX Runtime 会话、图片、GPU 显存和浏览器存储开销；源站容量估计可能缺失。
